How I work

Instruments

Almost everything here started on a five-inch screen. Termux was the first real instrument — a full Linux shell folded into an Android phone, no proper keyboard, no patience for shortcuts.

That constraint turned into a method: build tools that work where the environment refuses to cooperate, then confirm they hold up everywhere else. A phone forces you to know which parts of a system are essential and which are decoration — there's no room to carry dead weight.

I'm self-taught, which mostly means I've broken more things than I was ever taught not to. It's a slow way to learn, but it's an honest one — every fix comes with a reason attached.

Postmortems

Misreadings

Every bug I've spent more than two hours on has taught me something I didn't know I didn't know. These are the ones that rewired my mental model.

PM–01

GOROOT path bug in the Termux installer

The installer assumed Go lived at /usr/local/go. On Termux it's /data/data/com.termux/files/usr/lib/go. I spent an hour blaming the script before checking the actual path. Now every build step probes $GOROOT first.
PM–02

A nested tools/tools/ folder

ReconOS's plugin discovery walked ./tools and found a git-submodule subfolder also named tools — and double-registered every plugin inside it. Fixed by canonicalizing paths and skipping any folder whose resolved path matches an already-loaded plugin's parent.
PM–03

An async stdout/stderr deadlock

The orchestrator spawned subprocesses and read stdout and stderr sequentially. Once a tool wrote past the pipe buffer on stderr, it blocked waiting for a reader that was still stuck on stdout. Fixed by reading both streams concurrently with asyncio.gather().
PM–04

Believing the error message

The installer reported "permission denied" on a file that was world-readable. The real cause was a parent directory mounted with noexec. The error was technically true and completely misleading. Now I check mount options before trusting any permission message.

How I handle findings

Disclosure Practice

Verify before you write. I don't report anything I can't reproduce cleanly. Every report includes a clear reproduction, the affected system, and no speculation about impact I can't prove — findings are graded Confirmed, Probable, or Hypothesis, and the grade stays honest even when it's less impressive.

I document conservatively — what I observed, not what I suspect — and I wait on organizational timelines rather than mine. Disclosure is a conversation, not a deadline. I've reported across education, government-adjacent, and public infrastructure, and I don't name targets here.

— this is the ethic that separates research from noise.
